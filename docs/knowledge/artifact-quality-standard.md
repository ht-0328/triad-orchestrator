# 成果物品質基準

この基準は、要求整理からリリース準備までの全成果物に適用する。工程固有の形式は`templates/artifacts/`を使用する。

## 完了条件

成果物は、次の条件をすべて満たしたときだけ完了とみなす。

1. **目的と読み手**：誰が何を判断・実行する文書かを冒頭で説明している。
2. **結論先出し**：推奨案または結果を先に示し、理由、根拠、詳細の順で書いている。
3. **範囲**：対象、対象外、前提、制約を区別している。
4. **追跡可能性**：要求、設計判断、タスク、テスト、リリース証跡を安定IDで相互参照できる。
5. **検証可能性**：「適切」「高速」「十分」などの曖昧語を避け、観測方法と合格条件を示している。
6. **代替案と不利益**：重要な判断について、採用案だけでなく比較した案とトレードオフを残している。
7. **失敗時の動作**：正常系だけでなく、入力不正、依存障害、タイムアウト、再試行、復旧を扱っている。
8. **安全性**：認証、認可、秘密情報、個人情報、監査、破壊的操作の境界を示している。
9. **運用性**：ログ、メトリクス、アラート、バックアップ、移行、ロールバックを必要に応じて扱っている。
10. **根拠の区別**：確認済み事実、推論、基盤としての決定、未決事項を混同していない。
11. **現在性**：変化する外部仕様には参照先と確認日を付け、公式情報で再確認している。
12. **独立レビュー**：作成者以外が内容と証跡を確認し、判定を記録している。

## 安定ID

| 対象 | 形式例 |
|---|---|
| 機能要件 | `FR-001` |
| 非機能要件 | `NFR-001` |
| 設計判断 | `ADR-001` |
| リスク | `RISK-001` |
| タスク | `TASK-001` |
| テスト | `TEST-001` |
| 人間判断 | `DEC-001` |

番号を再利用しない。削除した項目は欠番のまま残し、置換先を記録する。

## レビュー時の重大度

| 重大度 | 判断基準 | 完了への影響 |
|---|---|---|
| Blocker | データ損失、権限逸脱、仕様違反、検証不能など、作業継続が危険 | 必ず停止 |
| Major | 主要要件の欠落、設計矛盾、再現可能な重大不具合 | 修正後に再レビュー |
| Minor | 限定的な不備、明確性や保守性の不足 | 原則修正。延期理由を記録可能 |
| Note | 将来改善、質問、参考情報 | 判定を妨げない |

## 出典

- `SRC-WRITE-001`：重要度順の説明と結論先出し。
- `SRC-WRITE-002`：Markdownによる見出し構造と可読性。
- `SRC-WRITE-003`：読み手・目的・情報選択・一文一義・レビュー。
- `SRC-ARCH-001`：品質属性とトレードオフを含む設計判断。
- `SRC-ARCH-005`：理解しやすい命名と小さな責務。
- `SRC-AI-001`、`SRC-AI-002`：役割、入出力契約、評価、ガードレール。
