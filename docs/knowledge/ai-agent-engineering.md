# AIエージェント開発チェックリスト

AIを増やすこと自体を目的にせず、責務、権限、入出力、評価方法を分離できる場合にだけ役割を分ける。

| 観点 | 必須の確認 | 問題例 |
|---|---|---|
| 目的 | 各AIの担当成果と完了条件が一文で説明できる | 全AIへ同じ曖昧な依頼を送る |
| 入力契約 | Git追跡ファイル、ハッシュ、期待出力、期限が引き継ぎに含まれる | チャット履歴だけに依存する |
| 出力契約 | スキーマ、判定語彙、人間判断の欄を検証する | 自由文を成功として扱う |
| 権限 | 読み取り、書き込み、ネットワーク、コマンドを役割ごとに最小化する | 調査担当が仕様やコードを変更できる |
| 独立性 | 作成者とレビュー担当が異なる | 実装者が自作コードを承認する |
| 停止条件 | 仕様矛盾、承認済み成果物変更、認証不足、危険操作で停止する | AIが仮定で承認済み仕様を変更する |
| 外部情報 | URL、参照日、版、事実と推論を記録する | 最新情報を記憶だけで断定する |
| 評価 | 合格基準、反例、失敗例、再現手順を持つ | 出力が自然に見えるだけで合格する |
| 再試行 | 読み取り処理だけを制限付きで再試行し、副作用処理は自動再試行しない | タイムアウトした実装を無条件に再実行する |
| 監査 | プロンプトハッシュ、担当、時間、終了状態を記録し、秘密情報は保存しない | 生の会話と認証情報をGitへ保存する |

## プロンプトの最低要素

1. 役割と今回の目的
2. 信頼できる入力の場所
3. 守るべき承認済み制約
4. 許可された操作と禁止操作
5. 出力スキーマと判定語彙
6. 人間へ上げる判断事項
7. 完了条件と失敗時の扱い

プロンプトだけを安全境界にしない。ファイル権限、使い捨て作業領域、コマンド許可、スキーマ検証、独立レビューを併用する。

## 出典

- `SRC-AI-001`：マルチエージェントの役割、協調、引き継ぎ、評価。
- `SRC-AI-002`：生成AIアプリケーションのパターン、ガードレール、評価。
- `SRC-AI-003`：文脈、明示的指示、出力形式、反復改善。

モデル、CLI、コンテキスト上限、認証方式は変化するため、採用時に各社の公式情報を確認する。
