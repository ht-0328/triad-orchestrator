# AWS・クラウド設計チェックリスト

この文書はAWSの概念整理に使う。サービス仕様、料金、上限、推奨構成は変化するため、設計時にAWS公式情報で再確認し、確認日を記録する。

| 観点 | 必須の記録 | 問題例 |
|---|---|---|
| 責任分界 | AWS、運用者、アプリケーションの責任を分ける | マネージドサービスなら設定不要と考える |
| 環境境界 | 組織、アカウント、リージョン、環境、所有者を示す | 本番と検証を同じ権限で運用する |
| IAM | 人、ワークロード、CIごとに最小権限と一時資格情報を使う | 長期アクセスキーをリポジトリへ置く |
| ネットワーク | 公開面、通信方向、名前解決、出口、管理経路を示す | すべてのポートを全世界へ公開する |
| データ | 分類、暗号化、鍵、保持、削除、バックアップ、復元試験を示す | バックアップ取得だけで復元を試さない |
| 可用性 | 障害単位、目標、冗長化、縮退、復旧手順を示す | マルチAZという語だけで保証する |
| 観測 | ログ、メトリクス、トレース、監査、通知、保持期間を示す | 障害後にログが不足している |
| 変更 | IaC、レビュー、段階リリース、ロールバックを示す | コンソールで本番を直接変更する |
| コスト | 主な費用要因、予算、タグ、アラート、停止条件を示す | リクエスト外の転送・ログ費用を無視する |
| 制約 | リージョン対応、クォータ、データ所在地、契約条件を確認する | 書籍の古い仕様値をそのまま採用する |

本基盤の自動実行から、AWS資格情報、本番変更、デプロイ、破壊的操作へ到達させない。クラウド変更は別の人間承認ゲートを必要とする。

## 出典

- `SRC-AWS-001`：クラウドの基本概念、責任分界、主要サービスの役割。
- `SRC-AWS-002`：AWSの構成要素、ネットワーク、セキュリティ、運用の全体像。

出典は概念理解の補助であり、現行仕様の根拠にはAWS公式文書を使用する。
